# Audit log

This is the living list of important problems in FitnessGuruSG. It is a register, not a diary of every edit.

`PROJECT_STATUS.md` is the story of what the product can do today. `docs/testing/` holds test plans and old test logs. `docs/archive/` holds past write-ups. None of those is a table you can scan for "what is still broken." This file is that table.

## How to use this file

- Read the table before you start a fix, so you do not trip over a known problem.
- One row is one finding. Keep the ID forever. Do not reuse an ID, and do not delete a row when it is fixed.
- When a pull request starts to fix a row, set **Status** to `in PR` and add the pull request link.
- When that pull request is merged and you have checked the fix, set **Status** to `fixed` and add the date.
- New problems get the next free ID (`AUD-022`, then `AUD-023`, and so on) and today's date.
- **Severity** is how much it matters if it stays: `critical`, `high`, `medium`, or `low`.
- **Area** is one of: security, data safety, bugs, dependencies, privacy, cleanup.
- Evidence is file paths only. Do not paste passwords, tokens, connection strings, or anyone's name, email, or phone number into this file.
- A row marked `to verify` was reported, and the code check for it is not finished yet. Every row below was checked by reading the code on 2026-11-12 (main, after pull request #1). None of them were clicked through on a phone for this log.
